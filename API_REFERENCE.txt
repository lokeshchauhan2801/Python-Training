Generated from the project's URLconfs, views, and serializers.

Change host/port to match where you run `python manage.py runserver`.

--------------------------------------------------------------------------------
 AUTHENTICATION (IMPORTANT — read first)
--------------------------------------------------------------------------------
DRF is configured with:
    DEFAULT_AUTHENTICATION_CLASSES = SessionAuthentication, BasicAuthentication
    DEFAULT_PERMISSION_CLASSES     = IsAuthenticated

There is NO token/JWT endpoint. So in Postman you authenticate one of two ways:

A) HTTP Basic Auth (simplest for the /api/v1/ endpoints)
   - Postman tab: Authorization -> Type: "Basic Auth"
   - Username: your Django user's username (or email, depending on your user model)
   - Password: that user's password
   - Works for every /api/v1/... endpoint below. No CSRF needed with Basic Auth.

B) Session cookie (needed for the browser-style /chat/, /company/ endpoints)
   1. Log in once via the admin: open http://127.0.0.1:8000/admin/ in a browser,
      log in. Postman can share the browser cookie if you enable the Postman
      "Interceptor"/"Cookie" sync, OR:
   2. Copy the `sessionid` (and `csrftoken`) cookies from the browser dev tools
      into Postman: Headers -> Cookie: sessionid=<...>; csrftoken=<...>
   3. For POST/PUT/PATCH/DELETE on session-authenticated endpoints, add header:
          X-CSRFToken: <value of the csrftoken cookie>

CSRF rules of thumb:
   - /api/v1/... with Basic Auth  -> no CSRF header required.
   - /api/v1/... with session cookie -> add X-CSRFToken for write methods.
   - /chat/..., /company/... (page/AJAX endpoints) -> session cookie +
     X-CSRFToken required for POST. These are NOT meant for Basic Auth.

Common headers:
   Accept: application/json
   Content-Type: application/json         (for JSON bodies)
   Content-Type: multipart/form-data      (for file uploads — Postman sets this
                                            automatically when you use form-data)

Notes on scoping:
   - Almost everything is "company-scoped". Objects belong to a Company you own.
   - On create, `company` is resolved automatically if you own exactly ONE
     company; if you own several you must pass `company: <company_id>`.
   - IDs are ULIDs (26-char strings), not integers.
   - List endpoints return only rows in your scope; out-of-scope IDs give 404.

 2) COMPANY API      base: /api/v1/company/
================================================================================
 DRF ModelViewSet (trailing slash required). Company-owner scoped.

2.1  GET  /api/v1/company/company/
     List companies you own.

2.2  POST /api/v1/company/company/
     Create a company.
     Body (JSON):
       {
         "name": "Acme Inc",
         "slug": "acme",                 // optional
         "description": "",              // optional
         "is_active": true               // optional
       }
     Server-controlled (ignored if sent): owner, created_by, updated_by.

2.3  GET  /api/v1/company/company/{id}/        Retrieve one company.

2.4  PUT  /api/v1/company/company/{id}/        Full update (send all writable fields).
     Example (note the REQUIRED trailing slash — a PUT without it returns 500):
       PUT {{base_url}}/api/v1/company/company/01M4Z5TXQ3MH7PT469SY6VY4P0/
     Headers:
       Content-Type: application/json
       Accept: application/json
       Authorization: Basic <username:password>
     Body (JSON):
       {
         "name": "Acme Inc (updated)",
         "slug": "acme-inc",
         "description": "Updated company description.",
         "is_active": true
       }
     Not writable (ignored / read-only): id, owner, created_by, updated_by,
       created_at, updated_at, is_deleted, deleted_at. `slug` must be unique.
     404 if the company is not yours (non-superuser). 400 on a duplicate slug.

2.5  PATCH /api/v1/company/company/{id}/       Partial update.
     Example:
       PATCH {{base_url}}/api/v1/company/company/01M4Z5TXQ3MH7PT469SY6VY4P0/
     Body (JSON) — send only the field(s) you want to change:
       {
         "name": "New name only"
       }

2.6  DELETE /api/v1/company/company/{id}/      Delete.
     Example:
       DELETE {{base_url}}/api/v1/company/company/01M4Z5TXQ3MH7PT469SY6VY4P0/

 3) CHAT API      base: /api/v1/chat/
================================================================================

3.1  POST /api/v1/chat/conversation/ask/
     Purpose : run ONE chat turn against an existing session (simple Q/A API).
     Body (JSON):
       {
         "session": "<session id — the `id` OR the `session_id` from the list>",
         "question": "What is in my uploaded document?"
       }
     NOTE on the session value: a ConversationSession has TWO ULIDs in the list
     response — `id` (the primary key) and `session_id` (a public reference).
     This endpoint accepts EITHER one, so copy whichever you like. (The two
     values differ; both resolve to the same session.)
     Returns : the created Conversation turn (question + response).
     Errors  : 503 if the LLM is not configured; 404 if session not in scope.

         "company": "<company_id>",      // optional if you own exactly one company
         "model_name": "",               // optional
         "context": {},                  // optional
         "media": [],                    // optional
         "metadata": {}                  // optional
       }

3.4  GET    /api/v1/chat/conversation-session/{id}/    Retrieve one.

 6) AGENTS API      base: /api/v1/agents/
================================================================================
 Three DRF ModelViewSets (SimpleRouter, trailing slash required):
 tool/, agent/, step/. Company-owner scoped (superusers see all; out-of-scope
 IDs give 404). Soft-deleted rows are excluded. These back the agent-builder
 canvas.

 Flow model: an Agent is a flow CONTAINER; its ordered Steps form a linear chain
 (entry Step has connected_from_start=true, each Step points at next_step, the
 final Step has connected_to_end=true). Each Step holds its own Tools.
 A company can have many Agents side by side. None of them is a company-wide
 "current" Agent and no endpoint marks one as current: the builder picks an
 Agent to edit, and each Chat session picks its own Agent
 (see 7.13 / 7.14).

 Read-only audit fields on every resource:
   id, created_at, updated_at, created_by, updated_by, is_deleted, deleted_at
 `company` is writable on create only (optional if you own exactly one company)
 and read-only on update.

 --- 6A) AGENT  /api/v1/agents/agent/ ---
 Fields: id, slug, name, order, company (+ audit fields above).
6.1  GET    /api/v1/agents/agent/                 List agents.
6.2  POST   /api/v1/agents/agent/
       Body (JSON):
         {
           "slug": "research",           // unique per company
           "name": "Research",
           "order": 0,                   // optional (default 0)
           "company": "<company_id>"     // optional if you own one company
         }
       400 {"slug": [...]} if the slug already exists for the company.
6.3  GET    /api/v1/agents/agent/{id}/            Retrieve.
6.4  PUT    /api/v1/agents/agent/{id}/            Full update.
6.5  PATCH  /api/v1/agents/agent/{id}/            Partial update.
6.6  DELETE /api/v1/agents/agent/{id}/            Delete.
6.7  GET    /api/v1/agents/agent/load/?company=<company_id>&agent=<agent_id>
       Canvas bootstrap payload. Both query params are optional (`company` is
       required only if you own several companies).
       Returns:
         {
           "agents": [ <Agent>, ... ],   // every agent of the company,
                                         // ordered by order, created_at
           "selected_agent_id": "<id>" | null,
           "steps":  [ <Step>, ... ],    // ALL steps of the selected agent
           "tools":  [ <Tool>, ... ]     // the company's tools, by slug
         }
       selected_agent_id = the in-scope `agent` param, else the first agent by
       (order, created_at), else null. A stale/foreign `agent` id never 404s;
       it silently falls back.

 --- 6B) STEP  /api/v1/agents/step/ ---
 Fields: id, agent, slug, name, tools, connected_from_start, connected_to_end,
         next_step, position_x, position_y, order, company (+ audit fields).
6.8  GET    /api/v1/agents/step/                  List steps.
6.9  POST   /api/v1/agents/step/
       Body (JSON):
         {
           "agent": "<agent_id>",        // required on create; read-only after
           "slug": "router",             // unique per agent
           "name": "Router",
           "tools": ["<tool_id>", ...],  // optional; same company as the agent
           "connected_from_start": false,// optional
           "connected_to_end": false,    // optional
           "next_step": "<step_id>",     // optional; same agent, not itself
           "position_x": 100,            // optional (canvas position)
           "position_y": 60,             // optional
           "order": 0                    // optional
         }
       (company is taken from the agent automatically.)
6.10 GET    /api/v1/agents/step/{id}/             Retrieve.
6.11 PUT    /api/v1/agents/step/{id}/             Full update.
6.12 PATCH  /api/v1/agents/step/{id}/             Partial update (e.g. link
                                                  wiring, tools, position).
6.13 DELETE /api/v1/agents/step/{id}/             Delete.

 --- 6C) TOOL  /api/v1/agents/tool/ ---
 Fields: id, slug, name, type, description, is_enabled, company (+ audit).
6.14 GET    /api/v1/agents/tool/                  List tools.
6.15 POST   /api/v1/agents/tool/
       Body (JSON):
         {
           "slug": "document_search",    // must be a registered handler slug
                                         // unless type == "langfuse"
           "name": "Document search",
           "type": "document_search",    // see types below
           "description": "",            // optional
           "is_enabled": true,           // optional
           "company": "<company_id>"     // optional if you own one company
         }
       Tool types: general_assistant, document_search, chat_summarise,
       web_search, add_to_knowledge_base, document_processing_status,
       langfuse (prompt-only; slug is the Langfuse prompt name).
6.16 GET    /api/v1/agents/tool/{id}/             Retrieve.
6.17 PUT    /api/v1/agents/tool/{id}/             Full update.
6.18 PATCH  /api/v1/agents/tool/{id}/             Partial update.
6.19 DELETE /api/v1/agents/tool/{id}/             Delete.
6.20 GET    /api/v1/agents/tool/available/?company=<company_id>
       List the registered handler functions the canvas can attach as tools.
       Returns: [ { slug, name, type, description, tool_id }, ... ]
       (tool_id is the existing Tool row id for the company, or null.)
6.21 POST   /api/v1/agents/tool/attach/
       Create a Tool row from a handler slug (idempotent per company+slug) and
       optionally attach it to a step.
       Body (JSON):
         {
           "slug": "document_search",    // required; an attachable handler
           "step": "<step_id>",          // optional
           "company": "<company_id>"     // optional if you own one company
         }
       Returns the Tool (200). 400 {"detail": ...} if slug is missing/unknown
       or the step is not in the company.

 7) CHAT PAGE / AJAX ENDPOINTS      base: /chat/
================================================================================
 These power the chat UI. They use SESSION auth + CSRF (not Basic Auth).
 For POSTs, send header: X-CSRFToken: <csrftoken cookie value>.
 {session_id} is a 26-char ULID. Every {session_id} path segment below accepts
 EITHER the session's `id` (primary key) OR its `session_id` reference value
 from the list response — both resolve to the same session.

7.1  GET  /chat/                                   HTML chat page.
7.2  GET  /chat/{session_id}/                       HTML chat page, opens a session.
7.3  GET  /chat/companies-json/                     List selectable companies.
7.4  GET  /chat/models-json/                         List available models/providers.
7.5  GET  /chat/sessions-json/                        List sessions.
         Optional query: ?company=<company_id>
7.6  POST /chat/new/
         Create a session. Body (x-www-form-urlencoded):
           company=<company_id>          // optional
           agent_id=<agent_id>           // optional; same rules as 7.14.
                                         // Omitted -> no Agent (Normal RAG).
         The session payload includes selected_agent_id.
7.7  GET  /chat/{session_id}/messages-json/          List messages in a session.
         Includes selected_agent_id (null if none, or if the stored Agent was
         deleted or belongs to another company).
7.8  POST /chat/{session_id}/send/
         Send one chat turn. Body (x-www-form-urlencoded or form-data):
           question=<text>                           // optional if a file is attached
           model_name=<model id>                     // optional (e.g. deepseek-chat)
           provider=<provider>                       // optional (openai | deepseek)
           attachment_ids=<document_id>              // optional, repeatable
         Behaviours:
           - file attached + no text  -> assistant asks what to do.
           - "add this to the knowledge base" + attachment -> Temporal processing.
           - "what's processing / status of <id>" -> live status report.
7.9  POST /chat/{session_id}/attach/
         Upload a file to a session (stored as a chat attachment, not embedded).
         Body (form-data):
           file=<File>
         Returns: { id, title, file_type }. Use the returned id as attachment_ids
         on /send/.
7.10 POST /chat/{session_id}/delete/
         Delete a session. Body (optional): soft=1  (soft-delete; default is hard).
7.11 POST /chat/{session_id}/reprocess/
         Retry Temporal processing for a failed knowledge-base document.
         Body: document_id=<document_id>
7.12 GET  /chat/{session_id}/doc-status-json/
         Live processing status for the chat tracker.
         Optional query: ?ids=<document_id>,<document_id>
         Returns: { documents: [ {id, workflow_id, temporal_url, title, status,
                    status_display, stage, progress, backend, error, terminal} ],
                    all_done }
7.13 GET  /chat/agents-json/?company=<company_id>
         List the Agents selectable for Chat in a company.
         `company` is optional only if your active company is one you may use;
         otherwise 400 {"error": "Select a company first."}. An unknown or
         unauthorized company id gives 404.
         Returns (ordered by order, then oldest created_at first):
           { "agents": [ {"id": "<agent_id>", "name": "Research",
                          "slug": "research"}, ... ] }
7.14 POST /chat/{session_id}/selected-agent/
         Set or clear the Agent this session runs with. Body as JSON or form:
           {"agent_id": "<agent_id>"}   // select an Agent
           {"agent_id": null}           // clear (Normal RAG); empty form value
                                        // also clears
         `agent_id` is required. Out-of-scope session -> 404.
         Returns 200:
           { "id": "<session_id>", "company_id": "<company_id>",
             "selected_agent_id": "<agent_id>" | null }
         400 {"error": "Agent not found or unavailable for this company."}
         for a wrong type, blank string, malformed ULID, unknown/soft-deleted
         Agent, or an Agent from another company (format errors may instead
         say "agent_id must be a ULID or null"). The session is not changed on
         error. /send/ takes no agent id; it uses the session's stored Agent.

================================================================================
 QUICK POSTMAN SETUP CHECKLIST
================================================================================
 1. Create an Environment with variable:  base = http://127.0.0.1:8000
 2. For /api/v1/... requests: Authorization = Basic Auth (your Django login).
 3. For JSON bodies: Body -> raw -> JSON.
 4. For file uploads (documents upload, chat attach): Body -> form-data, set the
    file field Type to "File".
 5. For /chat/ and /company/ endpoints: log in via /admin/ in a browser, copy the
    `sessionid` + `csrftoken` cookies into Postman, and for POSTs add header
    X-CSRFToken = <csrftoken value>.
 6. Remember the trailing slash on every URL. ULIDs are 26-char strings.

 Typical end-to-end flow:
   a. POST /api/v1/company/company/                 (create a company)        [if none]
   b. POST /api/v1/chat/conversation-session/       (create a session)
   c. POST /chat/{session_id}/attach/               (optional: attach a file)
   d. POST /chat/{session_id}/send/                 (ask a question / chart / KB add)
   e. GET  /chat/{session_id}/doc-status-json/      (poll processing status)
