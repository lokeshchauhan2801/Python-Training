The chat lives inside the Unfold admin shell whose wrappers are, from the viewport down: #page (flex min-h-screen) -> #main (flex flex-col grow) -> .px-4 -> #content (container) -> #content-main -> #chat-root -> #chat-layout -> the two columns -> the scrollable lists. NONE of those Unfold wrappers set min-height:0, and `min-h-screen` is a MINIMUM not a cap, so a long Chats list expands every flex ancestor and GROWS THE WHOLE PAGE: at 100% zoom the right panel + composer get shoved below the viewport and only the left list shows (exactly the reported bug). A measured pixel height on #chat-layout alone cannot fix this because its ancestors are free to grow. Fix = the standard "min-height:0 flex chain" applied to the REAL ancestor chain, scoped to the chat page (body.chat-fixed-viewport, set from JS) so no other admin page is affected: * Pin #main to the viewport height (100dvh) and let it be a flex column that cannot grow past the viewport (min-height:0, overflow:hidden). * Give every intermediate wrapper (.px-4, #content, #content-main, #chat-root) flex + min-height:0 so the height constraint flows down instead of being broken by a default-min-content child. * #chat-layout fills the remaining space (flex:1, min-height:0) and hides its own overflow; its two columns are min-height:0 flex children whose inner lists (#chat-session-list, #chat-messages) scroll INTERNALLY (overflow-y:auto). The long Chats list now scrolls inside its column and never pushes the page down. The JS sizeChatLayout() still runs as a belt-and-braces fallback for browsers without dvh, but the CSS chain is what actually bounds the page. {% endcomment %} {% comment %} CRITICAL: on this page the Tailwind utility classes that create the flex behaviour (`.flex`, `.flex-col`, `.flex-1`, `.min-h-0`) DO NOT take effect — Unfold ships a prebuilt stylesheet and these utilities either are not emitted or lose to the cascade here, so every `.flex` element computes `display:block` (verified in the headless browser: #chat-layout and both columns rendered as block, so the Chats list stacked and grew the page). This is the real reason the two earlier fixes failed. Therefore we DO NOT rely on utility classes for the viewport-bounding/flex chain: every rule below is written with ID / tagged selectors that explicitly set display:flex, flex, min-height:0 and overflow, so the layout is correct regardless of whether the utilities apply. These rules win on specificity (id, or body.class descendant) over the utilities. {% endcomment %} {% endblock %} {% block content %}
